## Requirements

- A Rust toolchain that supports the workspace's 2024 edition.
- [Bun](https://bun.sh/) for the web interface and documentation site.

## Start the backend

From the repository root, set a private JWT signing secret and an initial
administrator password. Keep these values out of version control.

```sh
export LAKS_JWT_SECRET="$(openssl rand -hex 32)"
export LAKS_ADMIN_PASSWORD="replace-with-a-strong-password"
cargo run -p laks -- config init
cargo run -p laks -- -c laks.toml start
```

`config init` writes the default settings to `laks.toml`; the initial
administrator password is copied into that file when it is created. Protect the
file and do not commit it. The server listens on port `8080` by default, creates
the SQLite database and storage directory as needed, and applies database
migrations on startup.

If `laks.toml` already exists, `config init` will not overwrite it. Review its
`[setup]` section to configure the initial administrator account. The
administrator is created only when the database has no users.

## Start the web interface

In another terminal:

```sh
cd ui
bun install
bun run dev
```

Open `http://localhost:3000`. The UI uses `http://localhost:8080` as its default
API base URL. To point it at another API in a Nuxt deployment, set
`NUXT_PUBLIC_API_BASE`.

The backend's current CORS configuration allows the development origins
`http://localhost:3000` and `http://127.0.0.1:3000`.

## Run the documentation site

```sh
cd docs
bun install
bun run dev
```

Nuxt prints the local documentation URL when the development server starts.
