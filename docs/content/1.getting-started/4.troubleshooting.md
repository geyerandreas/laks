## The backend exits because `LAKS_JWT_SECRET` is missing

The server requires this environment variable at startup:

```sh
export LAKS_JWT_SECRET="$(openssl rand -hex 32)"
```

Keep the value stable across restarts so existing login tokens can be validated.
Use a secret manager or another protected mechanism outside local development.

## The initial administrator cannot sign in

The first administrator is created only when the database contains no users.
Its credentials come from the `[setup]` section of `laks.toml` at the time the
server initializes the database. Changing those settings after the account has
been created does not change that account's password.

## The UI cannot reach the API

Check that the backend is listening on port `8080` and that the UI's
`NUXT_PUBLIC_API_BASE` points to it. During local development, the backend only
allows the configured origins `http://localhost:3000` and
`http://127.0.0.1:3000`.

## Configuration initialization says the file already exists

`laks config init` never overwrites an existing file. Update `laks.toml`
yourself, or pass `--output` with a different path when initializing a separate
configuration.

## Package uploads do not appear in the registry

Package publishing and retrieval are not yet complete end to end. The UI's
package table is sample data; see [Python packages](/essentials/python-packages)
for details.
